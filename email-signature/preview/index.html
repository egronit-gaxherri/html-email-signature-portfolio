Browser Preview — Not an Outlook Rendering Test

This page renders the signature in your web browser, which uses a modern standards-compliant engine. Outlook Classic renders email through Microsoft Word, Gmail rewrites and strips CSS, and every client differs. A correct result here proves the markup is well-formed — it does not prove the signature renders correctly in any email client. Final verification must be performed in each target client. What this preview does and does not show

  • Shown: markup validity, spacing, typography, colour, image loading, and how the layout reflows at 375px.
  • Shown: link targets — tel:, mailto:, https:, and the Google Maps address link are all live and clickable here.
  • Not shown: Outlook Classic's Word engine, which ignores border-radius, max-width, and much else. Rounded corners will be square there — expected, not a defect.
  • Not shown: Gmail's CSS stripping and class rewriting, Yahoo's table spacing quirks, or client-specific dark-mode colour inversion.
  • Not shown: behaviour when images are blocked. To simulate, disable images in your browser and confirm the alt text reads sensibly and the layout holds.
  • Image paths: the production file uses relative paths so this preview works offline. They must be swapped for absolute HTTPS URLs before deployment — see docs/DEPLOYMENT.md.
  • Local server: if the frames above are empty, you opened this over file://. Some browsers block local iframes. Serve the project over HTTP instead — see the README.
