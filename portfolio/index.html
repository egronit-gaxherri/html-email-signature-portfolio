About

Specialised in email HTML

I build HTML email signatures and campaign templates that hold together across every major email client — including Outlook Classic, which renders mail through Microsoft Word's engine and breaks most modern CSS on contact.

Every line is written by hand. No templates, no drag-and-drop builders, no email frameworks. Email is not the web with a smaller viewport: it is a set of rendering engines with contradictory rules, and the work is understanding which constraint applies where — why tables are still structural, why inline CSS is mandatory, and why something flawless in a browser can collapse in an inbox.

The approach prioritises reliability and honest documentation. Each deliverable ships with a record of what was built, why each technical decision was made, and precisely what still needs verifying in the target client. I don't claim a client is tested unless it has actually been tested.

Workflow

Development process

The same eight steps on every email project, from design interpretation through to documented delivery.

Design interpretation

Read the design and mark every element that needs an email-specific implementation rather than a web one.

Structure first

Build the table skeleton and prove the spacing before a single colour or font is applied.

Inline the styling

Move every declaration onto the element that needs it, with email-safe fonts and explicit dimensions.

Outlook workarounds

Add MSO conditionals, ghost tables, VML fallbacks, and DPI control where the Word engine demands them.

Responsive behaviour

Add media queries as enhancement, then verify the layout still reads correctly with them stripped out.

Degradation checks

Block the images, disable the style block, and confirm the message still communicates everything essential.

Cross-client verification

Render across the target clients, record what differs, and fix only what genuinely warrants fixing.

Documented delivery

Ship the production file with installation steps, known limitations, and an explicit list of what remains unverified.

Case Study

Northstar Digital Solutions

What the brief demanded, which constraints bit hardest, and the specific decision made at each one.

Brief

A corporate signature and a campaign email for a technology consultancy whose clients sit largely in enterprise environments — meaning Outlook on Windows, with images blocked by default and IT policies nobody will change for an email.

Constraint

Outlook Classic renders through Microsoft Word. No flexbox, no grid, no max-width, no border-radius, and the entire <style> block discarded — including every media query.

Anything that only works because a media query fired is, in that environment, something that does not work.

Approach

Build the layout so it is already correct with zero CSS support, then add enhancement on top. Media queries improve mobile; they are never load-bearing. Every piece of contact information is live text, never baked into an image.

#
Problem
Decision
01
Outlook ignores max-width and margin: auto, so the 600px card refused to centre.
Wrapped the card in an MSO-only ghost table at a fixed width="600". Outlook obeys the table; every other client never sees it.
02
A padded <a> button collapses to plain text in Outlook, losing the clickable area.
Added a <v:roundrect> VML button with <w:anchorlock/> so the whole shape stays clickable, hidden from other clients by conditional comments.
03
Corporate gateways block images by default, which would have hidden the contact details entirely.
Kept every contact field as live text and used HTML entity checkmarks rather than icon images. With images off, nothing essential is lost.
04
Word's rendering engine upscales images on high-DPI Windows displays, blurring the logo.
Set <o:PixelsPerInch>96</o:PixelsPerInch> and <o:AllowPNG/>, and served 2× assets at half their pixel dimensions.
05
Nested tables produced phantom gaps that appeared in Outlook but in no browser.
Applied border-collapse: collapse with mso-table-lspace and mso-table-rspace set to 0pt on every table.
06
The original signature applied white-space: nowrap to the street address, forcing horizontal overflow on narrow phones.
Restricted nowrap to the phone, email, and URL rows, where breaking mid-value genuinely hurts. The address is allowed to wrap.
07
Placeholder image services are a live third-party dependency — one that had already gone dark, leaving broken images throughout.
Replaced every placeholder with real first-party assets generated from SVG sources and committed to the repository.
